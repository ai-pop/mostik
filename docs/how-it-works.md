# Как работает Мостик

Документ для тех, кому интересно, что происходит внутри: коротко и простым языком, но со всеми
деталями, которые нужны разработчику.

---

## 1. Общая картина

```
 ┌──────────────────┐        формат OpenAI        ┌───────────────┐      ┌──────────────┐      ┌────────┐
 │ ваша программа   │  POST /v1/chat/completions  │    Мостик     │      │   OpenCode   │      │ модель │
 │ игра, мод, бот,  │ ──────────────────────────► │  локальный    │ ───► │  локальный   │ ───► │ в облаке│
 │ скрипт, Postman  │ ◄────────────────────────── │    сервис     │ ◄─── │   агент      │ ◄─── │         │
 └──────────────────┘   ответ или поток SSE-чанков└───────────────┘      └──────────────┘      └────────┘
        127.0.0.1:4891             (как у OpenAI)      два процесса в папке       отдельный процесс
```

Три участника:

1. **Ваша программа** — та, которой нужен AI. Она ничего не знает про OpenCode; она умеет говорить
   на языке OpenAI API.
2. **Мостик** — переводчик и диспетчер. Принимает запрос в формате OpenAI, ведёт диалог с
   OpenCode, возвращает ответ в том же формате OpenAI.
3. **OpenCode** — открытый AI-агент, который умеет работать с моделями. Мостик запускает его
   локально и общается с ним по внутреннему HTTP/SSE.

---

## 2. Что происходит с одним запросом

1. Клиент отправляет `POST /v1/chat/completions` с заголовком `Authorization: Bearer <ключ>`.
2. Мостик проверяет ключ (не совпал — отдаёт `401` в формате ошибки OpenAI).
3. Имя модели переводится через таблицу алиасов: `gpt-4o` → `opencode/nemotron-3-ultra-free`.
   Незнакомое имя не считается ошибкой — уходит на модель по умолчанию.
4. История сообщений собирается в один запрос (сервис не хранит состояние между вызовами —
   как и обычный OpenAI API, вся история приходит от клиента).
5. Запрос отправляется локальному OpenCode; в начало добавляется системная инструкция
   (`ChatPreamble`) — она просит модель отвечать обычным текстом и не трогать файлы.
6. Ответ возвращается клиенту:
   * `stream: false` — обычный JSON, как у OpenAI (`choices[0].message.content`, `usage`);
   * `stream: true` — поток SSE: роль, затем чанки текста, затем причина завершения и `usage`.
7. «Размышления» модели (reasoning) передаются отдельным полем
   (`delta.reasoning_content` / `message.reasoning_content`) — клиент может их игнорировать.

**Параллельность.** Одновременно выполняется до `MaxConcurrent` запросов (по умолчанию 4),
остальные ждут в очереди. Слишком долгий запрос обрывается по `TimeoutSeconds`.

---

## 3. Tool calling (function calling)

Клиент может передать список инструментов (`tools` или устаревшие `functions`). Дальше:

1. Мостик добавляет в запрос описание инструментов.
2. Модель, если решит вызвать инструмент, возвращает специальный блок.
3. Мостик превращает его в стандартный ответ OpenAI: `tool_calls` с `id`, `type` и
   `function.arguments`, `finish_reason = "tool_calls"` (в потоковом режиме — чанками).
4. Клиент выполняет инструмент и присылает результат сообщением с ролью `tool` и `tool_call_id` —
   цикл повторяется.

Поддерживается `tool_choice`: `none`, `auto`, `required` и `{ "type": "function", "function": { "name": … } }`.
Если модель «забыла» вызвать принудительно выбранный инструмент, Мостик повторяет попытку с более
строгой инструкцией.

## 4. Порт, ключ, файлы

| Что | Где |
|---|---|
| Адрес API | `appsettings.json` → `Urls` (по умолчанию `http://127.0.0.1:4891`) |
| Внутренний порт OpenCode | `OpenCode.ServerPort` (по умолчанию `4097`; если занят — берётся свободный) |
| Ключ клиентов | `appsettings.json` → `OpenCode.ApiKey` |
| Рабочая папка агента | `OpenCode.WorkDir`; пусто — папка `workspace` рядом с программой |
| Логи сервиса | `server.log` и `server.err.log` рядом с программой, а также страница «Логи» в окне |
| Конфиг самого окна | `ui-settings.json` рядом с программой |

Ключ создаётся автоматически при первом запуске (`generate-key.ps1` или само окно, если конфига нет).

---

## 5. Процессы

Запуск `Запустить Мостик.cmd` поднимает два процесса:

* `opencode-openai-bridge.exe` — сервис (сам API). Работает в фоне, окна не показывает.
* `opencode-bridge-ui.exe` — окно управления. Умеет старт/стоп/рестарт сервиса, показывает логи,
  правит конфиг, следит за состоянием.

OpenCode запускается сервисом как дочерний процесс и живёт, пока идут запросы. Остановка сервиса
останавливает и его. Остановить всё сразу — `Остановить Мостик.cmd` или кнопка **«Остановить»** в окне.

---

## 6. Автоустановка OpenCode

Если OpenCode на компьютере не найден, Мостик скачивает официальный архив для Windows
(репозиторий `sst/opencode`, последний релиз) и распаковывает его в папку пользователя
(`%LOCALAPPDATA%\OpenCodeBridge\opencode\bin`). После распаковки запускается проверка
`opencode.exe --version` — если версия не читается, установка помечается как неуспешная и в окне
появится понятное сообщение.

Порядок поиска OpenCode: указанный в настройках путь → рядом с программой → `PATH` →
места установки npm/node → ранее скачанная копия → профиль пользователя.

## 7. Частые технические вопросы

**Можно ли открыть API для других устройств в сети?**
Да: замените `Urls` на `http://0.0.0.0:4891`, перезапустите сервис и разрешите порт в файрволе
(кнопка «Правило файрвола» в окне). Учтите, что тогда ключ становится единственной защитой.

**Работает ли без интернета?**
Нет: локальный только API, сами модели — в облаке.

**Сколько запросов выдержит?**
Столько, сколько задано в `MaxConcurrent`. При превышении запросы встают в очередь, а не падают.

**Что если модель отвечает «не тем» форматом?**
Мостик разбирает ответ и приводит его к формату OpenAI; нераспознанные куски текста не теряются.

**Как посмотреть, что происходит?**
Страница «Логи» в окне или `GET /admin/status` (там же версия, путь к OpenCode, счётчики).

## English (short)

Mostik is a local HTTP service that exposes OpenCode through the OpenAI API surface:
`GET /v1/models`, `POST /v1/chat/completions` (JSON and SSE streaming, `tools` supported),
`GET /healthz`, plus `/admin/*` endpoints for status, logs, OpenCode installation and shutdown.

Request flow: client → Mostik (auth, alias resolution, prompt assembly) → local OpenCode
(internal HTTP + SSE) → model → response converted back to the OpenAI schema, including
`delta.reasoning_content` for reasoning blocks and `finish_reason="tool_calls"` for tool calls.

Everything runs on the local machine: the service binds to `127.0.0.1`, the API key is generated
locally and stored in `appsettings.json`. Configuration, logs and the agent workspace all live in
the program folder; OpenCode is downloaded and verified automatically when missing.
